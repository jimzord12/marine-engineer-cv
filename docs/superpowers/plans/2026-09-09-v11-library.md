# V11 Marine CV Library Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task, inline with self-review checkpoints. Steps use checkbox syntax for tracking. Await the user's approval of this plan before implementation.

**Goal:** Αναπαραγωγή του κλειδωμένου v11 μέσω επαναχρησιμοποιήσιμων Typst components, και παραγωγή δύο CV καπετάνιου που αποδεικνύουν την ανεξαρτησία theme και γραφικών.

**Architecture:** Δεδομένα, theme, artwork pack, layout profile και σύνθεση εγγράφου έχουν διαφορετικές ευθύνες. Οι μικρές Typst functions παράγουν περιεχόμενο και συνθέτονται σε sections. Η τελική κατανομή σελίδων παραμένει ρητή και προσαρμόσιμη, με οπτικό έλεγχο στο πραγματικό περιεχόμενο.

**Tech Stack:** Typst 0.15.1, υπάρχουσες bundled OFL γραμματοσειρές, native SVG, PowerShell. Python/PyMuPDF και Poppler μόνο για development verification, όχι ως προϋπόθεση παραγωγής ενός CV.

**Spec:** Το παρόν περιλαμβάνει την τελική προδιαγραφή, βάσει του εγκεκριμένου `designs/11-flagship-balance.typ` και `exports/review/Marine-Engineer-CV-v11.pdf`. Αντικαθιστά το παλιό `2026-09-09-component-library.md`.

## Global Constraints

- Το v11 έχει εγκριθεί και κλειδωθεί. Δεν τροποποιούμε τα αρχεία αναφοράς, τα δεδομένα ή τα γραφικά από τα οποία εξαρτάται.
- Το «80–85% ίδιο» αφορά την επαναχρησιμοποίηση του προηγούμενου σχεδίου αρχιτεκτονικής. Δεν επιτρέπει οπτική απόκλιση 15–20%: το engineer αποτέλεσμα πρέπει να είναι οπτικά ίδιο με το v11.
- Δεν υλοποιούμε πριν από την έγκριση αυτού του πλάνου. Μετά την έγκριση, εκτελούμε όλες τις φάσεις αυτόνομα, χωρίς ενδιάμεσες ερωτήσεις για συνήθεις επιλογές.
- Οι υπάρχουσες εκδόσεις παραμένουν προσβάσιμες. Δεν διαγράφουμε, μετακινούμε ή αντικαθιστούμε ιστορικά PDFs για να καθαρίσουμε το repo.
- Δημιουργούμε νέα outputs σε νέους φακέλους· αποτυχία αν ο προορισμός υπάρχει. Μόνο κανονικά additive commits/pushes, χωρίς destructive Git.
- Δημόσια παραδείγματα με φανταστικά στοιχεία και σαφή disclosure. Δεν χρησιμοποιούμε προσωπικά στοιχεία φίλων.
- Experience: εταιρεία → τύπος πλοίου → πλοίο. Δεν επαναφέρουμε μηχανές, ισχύ, αρμοδιότητες ή αυτόνομα entries ανά μπάρκο.
- Χρόνοι σε ακέραιους μήνες υπηρεσίας, μορφοποιημένοι σε χρόνια/μήνες. Οι ημερολογιακές περίοδοι εταιρειών δεν χρησιμοποιούνται για υπολογισμό υπηρεσίας.
- Μία κοινή επιλογή για την εμφάνιση χρόνων σε ΟΛΑ τα πλοία. Αν είναι κρυφοί, η τρίτη στήλη δεν αποδίδει περιεχόμενο αλλά διατηρεί τον χώρο της. Vessel name και rank παραμένουν στις ίδιες θέσεις, με ίδια πλάτη στηλών και gaps. Δεν υπάρχουν per-row toggles ούτε μετακίνηση του rank δεξιά.
- Synopsis μία φορά, μετά την ολοκλήρωση του Experience: συνολική υπηρεσία, μοναδικά πλοία, μοναδικές εταιρείες.
- Certificates διατηρούν τον εγκεκριμένο σχεδιασμό. Education και languages είναι επεκτάσιμες λίστες.
- Δύο σελίδες για τα τρία βασικά παραδείγματα. Πρόσθετο τρισέλιδο fixture για μεγαλύτερο περιεχόμενο. Καμία καθολική σμίκρυνση γραμματοσειρών για να χωρέσουν όλα.
- Selectable PDF text, embedded fonts, decorative artifacts. Δεν παρουσιάζουμε τους ελέγχους εξαγωγής ως πιστοποίηση από εμπορικό ATS.

## 1. Τι έδειξε η ανάγνωση του τελικού κώδικα

Η θεμελιώδης διάσπαση σε hero, sections, page shell και μικρά primitives παραμένει. Αλλάζουν συγκεκριμένα:

1. Το παλιό VoyageEntry/VesselSpecs/SeaServiceList αντικαθίσταται από CompanyExperience/VesselTypeGroup/VesselRow/ExperienceSection.
2. Το EngineeringToolkit αφαιρείται. EducationEntry και LanguageEntry αποτελούν το EducationLanguagesSection.
3. Το Synopsis έχει δικό του υπολογισμό δεδομένων και ανεξάρτητη απόδοση. Δεν είναι footer σελίδας.
4. Το v11 χρησιμοποιεί bottom margin 15 mm στην πρώτη και 11 mm στη δεύτερη σελίδα, company gaps 8/4 mm, row gaps 3.5/2.5 mm, και ελαστικό κενό πριν από το section 3. Αυτές είναι αποφάσεις layout profile, όχι «μαγικοί αριθμοί» διάσπαρτοι στα components.
5. Το show-vessel-durations σήμερα κρύβει μόνο την απόδοση. Θα διατηρήσουμε αυτή τη συμπεριφορά αλλά θα υποστηρίξουμε και δεδομένα με μόνο company totals όταν οι αναλυτικοί μήνες δεν είναι διαθέσιμοι.
6. Το υπάρχον `screw` list marker είναι πλέον ανενεργό στο εγκεκριμένο sample. Δεν δημιουργούμε production Bullet component μόνο για να συμπληρώσουμε έναν αριθμό components.

## 3. Συμβόλαια

Οι κλήσεις παρακάτω ορίζουν το API-στόχο· τα ονόματα υλοποίησης είναι kebab-case.

```typst
#import "../lib.typ": flagship
#import "../themes/flagship.typ": theme
#import "../roles/engineer.typ": artwork
#import "../layouts/flagship-v11.typ": layout
#let candidate = json("../content/extended-company-example.json")
#show: flagship.with(candidate: candidate, theme: theme,
  artwork: artwork, layout: layout, show-vessel-durations: true)
```

| Σύνθεση | Inputs / ευθύνη |
|---|---|
| `flagship` | candidate, theme, artwork, layout, κοινό toggle· συνθέτει document shell και sections |
| `hero` | identity, contacts, theme, artwork, hero geometry· κατέχει θέσεις και overlap |
| `contact-group` | ordered items, alignment, theme, gap· κανένα hardcoded Availability/Discipline |
| `vessel-row` | vessel, show-durations, theme· επιστρέφει cells, ώστε ο γονέας να κρατά κοινές στήλες |
| `vessel-type-group` | group, show-durations, theme, spacing· ελέγχει κοινό grid |
| `company-experience` | company, theme, spacing, show-durations· date column και nested groups |
| `experience-section` | company fragments, title/continuation, theme, layout· όχι αυθαίρετα pagebreaks |
| `synopsis` | computed totals, theme, spacing· ίδιο gap 3 mm και ίδιο style μονάδων |
| `education-languages-section` | δύο arrays, theme, spacing· δεν επιλέγει από μόνο του θέση στο κάτω μέρος |
| `document-shell` | theme, artwork, page settings, body· page-wide rules και backgrounds |

Τα leaf components δεν διαβάζουν JSON, δεν γνωρίζουν «engineer» ή «captain», και δεν επιλέγουν theme. Οι γονείς ορίζουν εξωτερικά κενά· τα παιδιά εσωτερικά paddings/στοιχίσεις.

**Theme:** semantic colors `ink`, `hero`, `accent`, `metal`, `muted`, `surface`, `paper`, `plate`, `rule`, `on-hero`; fonts `body`, `display`; named text styles για name/rank/labels/company/duration/metric/body. Κανένα νέο literal χρώμα/font μέσα σε leaf components.

**Artwork:** slots `portrait-backdrop`, `portrait-frame`, `hero-left`, `hero-right`, `background-first`, `background-continuation`, `profile-illustration`. Καθένα περιέχει πηγή και προαιρετικά width/x/y/opacity. Τα SVG του νέου pack παίρνουν χρώματα από semantic palette placeholders. Τα παλιά αρχεία δεν αλλάζουν: η υλοποίηση μπορεί να δημιουργήσει αντίγραφα με παραμετρική παλέτα, αλλά ο default engineer renderer πρέπει να παραμένει pixel-identical.

**Layout:** πρώτη/επόμενες σελίδες, margins, fixed hero height, company/row gaps, heading gaps, synopsis gap, education bottom anchoring και company allocations. Προεπιλογή: πρώτες τρεις εταιρείες στην πρώτη σελίδα, υπόλοιπες στη δεύτερη, synopsis μετά την τελευταία. Η αλλαγή theme δεν αλλάζει αυτή τη σύνθεση· επιτρέπονται typography settings στο theme και μικρές asset corrections στο artwork.

**Data:** adapter του υπάρχοντος JSON χωρίς αλλαγή στο frozen αρχείο. Στο normalized schema, εταιρείες και πλοία έχουν σταθερά IDs, groups έχουν type, rows έχουν vessel-id/name/rank/months. Contacts/certificates/education/languages είναι arrays με named fields. Επαναλαμβανόμενος vessel-id σε διαφορετικούς βαθμούς ή εταιρείες μετρά μία φορά στο unique vessels αλλά η υπηρεσία αθροίζεται ανά entry. Δεν συγχωνεύουμε rows διαφορετικών βαθμών και δεν μετράμε κενά μεταξύ συμβάσεων.

**Απουσία αναλυτικών χρόνων:** όταν το toggle είναι true απαιτούνται months σε κάθε row. Όταν false, εταιρεία μπορεί να δίνει `service-months` χωρίς αναλυτικά months. Αν δίνονται και τα δύο, απαιτείται ισότητα company total και αθροίσματος rows. Μερικώς συμπληρωμένοι μήνες επιτρέπονται μόνο με explicit company total και κρυφούς χρόνους. Ποτέ σιωπηλό zero για άγνωστο χρόνο. Οι περίοδοι εταιρειών είναι display strings.

Verification contract:
```python
assert len(actual) == len(reference) == 2
for expected_page, actual_page in zip(reference, actual):
    assert expected_page.get_pixmap(matrix=fitz.Matrix(2, 2)).samples == actual_page.get_pixmap(matrix=fitz.Matrix(2, 2)).samples
    assert ' '.join(expected_page.get_text().split()) == ' '.join(actual_page.get_text().split())
```

Run: `python tests/verify.py --reference exports/review/Marine-Engineer-CV-v11.pdf --actual <fresh-build>/engineer.pdf --mode exact --output <fresh-evidence>`.

## 5. Αυτόνομη εκτέλεση μετά την έγκριση

Κάθε task τελειώνει με έλεγχο και μικρό commit όταν έχει ανεξάρτητο νόημα. Δεν χρειάζεται ανθρώπινη έγκριση ανά phase. Συνήθεις τεχνικές επιλογές και βελτιώσεις boundaries γίνονται αυτόνομα εντός της προδιαγραφής. Δεν μεταβάλλουμε το frozen design για να βολέψει η υλοποίηση.

Αν εμφανιστεί πραγματικό εμπόδιο που απαιτεί μη εξουσιοδοτημένη καταστροφική ενέργεια ή απόφαση που αλλάζει το εγκεκριμένο αποτέλεσμα, σταματάμε μόνο το εξαρτώμενο βήμα και εξηγούμε συγκεκριμένα το εμπόδιο. Δεν θεωρούμε την απουσία του χρήστη άδεια για αλλαγή του scope.
